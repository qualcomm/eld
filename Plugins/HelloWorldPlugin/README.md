# HelloWorldPlugin

HelloWorldPlugin is a minimal ELD linker-plugin example. It registers a
LinkerPlugin and implements its lifecycle hooks without modifying the link
or requiring plugin options.

## Loading the plugin

Use the supplied HelloWorldPlugin.yaml, or this configuration:

```yaml
GlobalPlugins:
  - Type: LinkerPlugin
    Name: HelloWorldPlugin
    Library: HelloWorldPlugin
```

Pass `--plugin-config /path/to/HelloWorldPlugin.yaml --trace=plugin` to ELD.
Tracing reports Init, VisitSections, ActBeforeRuleMatching,
ActBeforeSectionMerging, ActBeforePerformingLayout, ActBeforeWritingOutput,
and Destroy. Make the built plugin directory and the package runtime library
directory available through LD_LIBRARY_PATH on Linux, DYLD_LIBRARY_PATH on
macOS, or PATH on Windows. CTest does this automatically.

## Build and test as part of ELD

Configure ELD normally, then build the plugin:

```sh
cmake --build /path/to/build-eld --target HelloWorldPlugin
```

The plugin-local lit test is included in ELD's configured regression targets.
To run just this test, use the architecture-specific driver generated by the
ELD build, supplying the shared plugin configuration's build directories:

```sh
/path/to/build-eld/test/llvm-lit-riscv64-default -v \
  -Deld_obj_root=/path/to/build-eld \
  -Dllvm_tools_dir=/path/to/build-llvm/bin \
  -Dllvm_libs_dir=/path/to/build-llvm/lib \
  -Deld_test_target=RISCV64 \
  /path/to/eld/Plugins/HelloWorldPlugin/test
```

Adjust the architecture and build directories to the configured ELD/LLVM
build. Normal ELD regression targets supply these parameters automatically.

## Build standalone

The complete Plugins directory can be copied outside either source tree.
Use its top-level CMakeLists.txt, not this plugin directory:

```sh
cmake -S /path/to/Plugins -B build-helloworld \
  -DBUILD_STANDALONE_PLUGINS=ON \
  -DELD_PACKAGE_ROOT=/path/to/target_tools \
  -DCMAKE_CXX_COMPILER=/path/to/host-clang++ \
  -DCMAKE_CXX_FLAGS="-stdlib=libc++" \
  -DELD_PLUGINS=HelloWorldPlugin
cmake --build build-helloworld
```

The host compiler and C++ runtime must match the installed ELD ABI.
On Linux, the standalone framework automatically selects the package's host libc++
libraries for compiler probes and plugin links, avoiding accidental system
runtime selection. The host's default libc++ can introduce ABI or unwinder
dependencies incompatible with the ELD linker's packaged runtime, even if the
plugin links successfully. The framework does not select headers or embed
RPATH/RUNPATH; the loading environment must supply runtime library paths. See the
[runtime configuration guide](../README.md#package-c-runtime-libraries-linux).
CMAKE_CXX_FLAGS also applies during CMake's compiler checks. Do not use a
target compiler to build the host plugin. Conventional include/lib/bin and
Tools/include, Tools/lib, Tools/bin package layouts are both supported.
The Linux library is build-helloworld/HelloWorldPlugin/libHelloWorldPlugin.so;
other platforms and multi-configuration generators use their normal output
names and configuration subdirectories.

Building alone needs no target compiler or test tools. To enable smoke tests
using Python's standard library and the package's target compiler and linker:

```sh
cmake -S /path/to/Plugins -B build-helloworld -DBUILD_TESTING=ON
cmake --build build-helloworld
ctest --test-dir build-helloworld --output-on-failure
```

This reuses the package and compiler settings cached by the first command.
CMake discovers ELD_TARGET_CXX, ELD_TARGET_CC, and ELD_TARGET_LD under the
resolved package's bin directory, preferring clang/clang++ and retaining
hexagon-clang/hexagon-clang++ fallbacks. Set explicit paths only for tools
elsewhere or to override that choice.

## Add external lit tests

Reconfigure the same build with an external LLVM lit runner:

```sh
cmake -S /path/to/Plugins -B build-helloworld \
  -DBUILD_TESTING=ON \
  -DELD_ENABLE_LIT_TESTS=ON \
  -DELD_TARGET_TRIPLE=riscv64-unknown-elf \
  -DELD_LLVM_LIT=/path/to/llvm-package/bin/llvm-lit
cmake --build build-helloworld
ctest --test-dir build-helloworld --output-on-failure
```

Use the target triple supported by your package. The lit architecture is
derived from ELD_TARGET_TRIPLE; ELD_TEST_TARGET overrides it when necessary.
ELD_TARGET_CXX_FLAGS and ELD_TARGET_LD_FLAGS provide extra test-input compiler
and linker flags. They do not change host plugin compilation.

The smoke test is named ELDStandalone.HelloWorldPlugin, and the lit test is
ELDStandaloneLit.HelloWorldPlugin; select either with `ctest -R`. Lit needs
FileCheck and not in ELD_LLVM_TOOLS_DIR (default: beside llvm-lit); LLVM
libraries default to the sibling lib directory. Override ELD_LLVM_TOOLS_DIR
and ELD_LLVM_LIBS_DIR for split installations. HelloWorld needs no readelf.
The standalone lit configuration does not load eld/test/lit.cfg.

For a direct smoke-test invocation without CTest:

```sh
python3 /path/to/Plugins/HelloWorldPlugin/test/standalone_test.py \
  --plugin-dir build-helloworld/HelloWorldPlugin \
  --tools-dir /path/to/target_tools \
  --target-cxx /path/to/target_tools/bin/clang++ \
  --target-ld /path/to/target_tools/bin/ld.eld \
  --target-triple riscv64-unknown-elf
```

Use the resolved Tools directory for --tools-dir when the package contains
one. Override --library-dir and --runtime-dir for custom library locations.
Use `--target-cxx-flags=-G0` or `--target-ld-flags=--emit-relocs` syntax for
dash-leading arguments.

See [the plugin framework README](../README.md) for package discovery,
platform limitations, and the CMake helper interface.
